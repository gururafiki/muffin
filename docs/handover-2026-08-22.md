What is **not** done, what is **draining on its own**, and what to **watch**. Everything here was
measured against production on 2026-08-22 rather than estimated; where a number is a sample, the
sample size is given.

For what exists, see [data-coverage.md](data-coverage.md). For how it works, see

## 1. Read this first — the two failure shapes that keep recurring

Almost every defect found in the last week was one of these. If you are handed a symptom, start by
asking which it is.

**A number that is merely present twice.** Both copies agree, so no floor, unit band, count or
freshness rule can see it. AAPL's annual revenue was plotted twice for 2025 and 2024 — visible only
on the rendered page. Fixed in migration 126, guarded by `check_one_period_one_point.py`.

**A backlog that empties by MARKING looks exactly like one that empties by WORKING.** Every
`*_missing_at` column exists because this was rediscovered. A resource reporting `ok: true` with a
falling `remaining` may be recording "the provider has nothing" for securities it asked about under
the wrong name. Compare the two populations, never one count.

A corollary that cost real time this week: **a plan's own estimate of rarity is not a measurement.**
The duplicate-period issue was sized in the plan at "0 of 252 securities sampled" and re-measured at
5 of 142 (3.5%).

## 2. Not done — with the reason, not just the status

### 2.1 ~610 large holdings can never get EPS history (the largest open gap)

`equity/fundamental/historical_eps` has exactly one working provider — alpha_vantage, **25 calls a
DAY** — and FMP's copy is 402 premium even for AAPL, so there is no second source. It serves **US
listings**.

The problem is which symbol we hold. OpenFIGI's US lookup returns the thin OTC foreign-ordinary line
for most foreign companies, and those are *bare* tickers, so a suffix filter passes them:

| we hold | provider answers | the company's real US line |
|---|---|---|
| `ASMLF` | `{}` — zero keys | `ASML` (108 quarters) |
| `BUDFF` | `{}` | `BUD` — **not in our universe** |
| `NONOF` | `{}` | `NVO` — **not in our universe** |

`pending_eps_history` now requires a US listing in `market.listing`, which took the backlog from
1,015 to 394 and stopped ~621 wasted calls (each 4% of a day's budget). **The excluded companies are
not otherwise covered** — measured, only **2 of the top 40** have a US-listed sibling row; ASML and
TSM are the exception, not the rule. AB InBev's US rows are *bonds*.

**To close it:** resolve the ADR and promote it (`promote-listing` needs only a FIGI, and OpenFIGI's
`/v3/mapping` resolves a named ticker directly — `BABA` was done this way). This is a symbol-
resolution task, not an EPS one. Budget it against the 25/day quota: the backlog drains at ~24/day.

### 2.2 No UI for `security_eps_history`

Deliberate. `security_earnings_surprise` (migration 120) already powers a universe-wide last-surprise
line on the stock page, derived from data we hold. The alpha_vantage table is deeper (122 quarters
for MSFT) but covered **one security** at the time of writing, filling at ~24/day against 394.

A serving view choosing between the two sources — with tests, mutation proofs and an anon-latency
probe — is not proportionate for a section that would render for 1 in 12,000 securities. Revisit
when the backlog has drained enough that a page would actually show it.

### 2.3 `security_metric_series` resolves symbols the slow way

It joins `security_symbol`, which is a view over two LATERAL subqueries: resolving **one** symbol
through it scans all 27,629 securities. Migration 102 built the materialised `symbol_security` for
exactly this and fixed `price_series` (weekly chart 1,382 ms → 258 ms); this view was never moved
across.

Anon latency is currently **fine** (stock statements 472 ms against a 2,000 ms budget), so this is a
known inefficiency, not a defect. But it is the same shape that has ended in an anon timeout twice
(`fund_sector_weight`, `security_facets`), and it worsens as the universe grows. **Watch
`check_anon_read_latency.py`'s "stock statements" line.**

### 2.4 Everything in `notes.md` that is not a data question

`notes.md` holds a queue of product asks that were **not** part of this work and are untouched: TTL
changes, a per-page admin refresh button, tier-level growth on the map, infinite scroll on remaining
lists, a stock-page skeleton, search on more list pages, and the Studio edge-functions mount.

Three items in it are **already fixed** and should not be re-investigated — the code comments name
the original reports directly:

- Vietnam showing US sectors → a country with no coverage now says "No sector data for X"
- A country's sector returns not matching its own ETF → the country's own rows are used
- Missing gained/lost labels → a whole-universe performance fetch was silently truncated at
  `PGRST_DB_MAX_ROWS`; it now asks only for the symbols on the page

## 4. Guards that exist, and the one thing each cannot see

`market-verify.yml` runs daily at 03:00 UTC. It asserts **shape, not exceptions** — every defect it
was built for returned HTTP 200.

| guard | blind spot worth knowing |
|---|---|
| `check_one_period_one_point.py` | Watches the **7-day** collapse window and the 8–299 day band. A source with a *different* convention (a fiscal-year change, a 30-day offset) shows up in the second band; zero today |
| `check_derived_metrics.py` | Compares metrics to the filing they came from. Only covers rows with a `metric_source_field` mapping — `sec-xbrl` writes straight from company facts and has no statement to compare against |
| `check_quarter_is_a_quarter.py` | A **population median**, so it cannot flag one contaminated company; a volatile company cannot move the median either, which is the point. Has `--self-test` |
| `check_anon_read_latency.py` | Times the **conjunctions the app sends, as anon**, at a 2,000 ms budget against the 3,000 ms ceiling. It cannot see a query the app sends that is not in its list |
| `check_significant_holdings.py` | By fund **weight**, which is free of currency, cap and country — the mega-cap canary is US-only and blind to securities with no market cap |
| `check_retention_is_enforced.py` | 120-day threshold on a 90-day prune. Looser on purpose: a few days over means the cron is late, a month over means the delete stopped |

**Two facts about verification in this repo that are easy to lose:**

- A behaviour test proves the **rule** against a fixture. A market-verify check proves the rule is
  applied to the **data**. These are different claims — `security_price` passed every migration pass
  and was still unreadable for want of a grant.
- **A guard is not proven until you delete what it guards AND confirm the mutation reached the
  database or file.** Five separate forms of "the mutation silently did nothing" have been hit here:
  `sed` mis-escaping, wrong indentation, a migration that never applied, a fingerprint that returned
  an empty string, and a harness piping SQL through stdin to a test that reads the file.

## 5. Genuinely unavailable — do not re-probe without a new key

Re-measured 2026-08-22 **with live FMP and Alpha Vantage keys**, because a 402 from a keyless
deployment proves nothing:

- **`form_13f`** — 204 from SEC, and the schema rejects every other provider. No 13F holdings.
- **`revenue_per_geography`** — genuinely per-symbol premium: answers for AAPL/MSFT/NVDA/JPM/TSM,
  **402 for NEE, PLD, BHP, SAP.DE, 7203.T, 005930.KS, SHEL.L**.
- **News sentiment** — needs Benzinga; no key.
- **econdb indicator data** — the node cannot mint its own token (403 on `/user/create_token/` from
  this IP) and there is no free permanent key. FRED replaces it and its key is already configured;
  `economy/fred_search` returns 204, so a FRED catalogue must be curated series by series.

**One correction to an earlier justification, kept because it is the kind of thing that gets
re-derived wrongly:** `equity/compare/peers` was recorded as premium. With a live key it answers for
**all 13 symbols tried**. The decision to compute peers instead still stands, on better grounds —
FMP's peer list for AAPL runs from NVDA at $5.20T down to an **$852,000** company, which is a sector
grab-bag rather than a size-proximate set.

## 6. Open questions I did not resolve

- **Is `security_metric_series` worth moving to `symbol_security` now, or when latency degrades?**
  Moving it is a small migration; the risk is that adding a join changes the plan, which is exactly
  how `price_series` broke for anon and only for anon (migration 94). If you move it, **time it as
  anon under the app's conjunction before believing it**.
- **Should the duplicate `security_metric` rows be pruned at all?** Migration 126 collapses them on
  read and keeps both, deliberately — both are legitimate and provenance is worth more than the
  rows. Pruning would make the choice unrepeatable. Revisit only if the table's size becomes a
  problem, which it is not at 3.3M rows.
- **Splits outside the US remain invisible** (Tiingo 404s local foreign listings), so a Japanese
  split does not adjust our stored history. Dividends *are* global since migration 87. I did not
  measure how many stored series are affected.
